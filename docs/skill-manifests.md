# 技能包的依赖、预检、升级与对照评测

本文对应尚未发布的功能迭代，版本号保持不变。工作流画布、分支和并行执行方式见[技能组合与工作流](skills-workflows.md)。这里的“技能包”就是可保存、复用和导出的技能组合：一个主技能搭配辅助技能，在同一模型会话中完成任务；它不会把成员改写成一个新的 `SKILL.md`。

建议先声明依赖、预览补全、运行免费本地预检，再根据需要发起 AI 分析或对照评测。最后查看升级影响，明确选择要采用新版本的任务或工作流节点。

## 声明必需和可选依赖

在技能根目录放置 `tidebot.json`，与 `SKILL.md` 同级。技能详情中的依赖清单编辑入口也可以保存此文件；保存会创建新技能版本，旧版正文和其他资源保持原样。没有该文件的旧技能继续使用原来的方式运行，软件不会据此认定它没有未声明的依赖。

```json
{
  "format": "tidebot-skill/1",
  "dependencies": [
    { "skill_name": "research-helper" },
    { "skill_name": "format-guide", "optional": true },
    {
      "skill_name": "schema-guide",
      "content_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    }
  ],
  "environment": [
    { "kind": "command", "name": "python3" },
    { "kind": "python_package", "name": "requests", "version": "==2.32.3" },
    { "kind": "env", "name": "SERVICE_API_KEY" },
    { "kind": "file", "name": "scripts/check.py" },
    { "kind": "tool", "name": "Read" },
    { "kind": "mcp", "name": "github", "optional": true }
  ]
}
```

名称和 hash 都是格式示例，需要替换成自己的技能信息。`content_sha256` 可从技能依赖清单接口 `GET /api/skill-manifests/{skill_id}?version_id={version_id}` 返回的信息取得。它是“相对路径到文件摘要”映射的 SHA-256，不是 `SKILL.md` 单文件的摘要、Tidebot 内部的版本 ID 或版本表的 `content_hash`。库中的显示名称不参与此摘要，因此 ZIP 导入产生新的显示名称后，仍可以核对内容一致性。

- 未写 `optional` 的技能依赖为必需依赖。缺少、冲突或出现依赖环路时，需要处理后才能保存完整技能包或按该组合运行。
- `optional: true` 表示辅助能力可以不加入。发现可用候选时会提示，不会自动采用；显式加入后，该成员自身的必需依赖仍需要满足。
- `content_sha256` 要求确切内容。未选中的依赖可在已导入历史版本中查找匹配内容；已经选定的成员不匹配时会报告版本冲突，不自动替换用户选择。
- 解析仅使用本地已导入技能，同时识别库中名称与技能 frontmatter 的名称。无法唯一判断时要求明确选择，不从互联网自动下载或安装。

“预览依赖补全”会展示递归查到的成员候选和问题。点击采用后再保存，才会把候选加入当前编辑内容；它不是后台自动修改。技能包保存后固定所有成员版本，整个组合最多 16 个成员。必需依赖的递归展开也受这个上限约束。

清单最多 64 KiB，可声明最多 16 个直接技能依赖和 32 个环境项。`command` 只接受命令名，不能填写路径或命令参数；`file` 只接受技能包内部的安全相对路径。环境项也可以设置 `optional: true`。这一版不提供安装命令、自动修复环境或自动授予工具权限。

## 填写包说明和验收样例

技能包可以保存用途说明、使用说明、输入提示、输出提示，以及验收样例。这些说明随包版本保存并通过 ZIP 导入导出。旧客户端更新时未传 `details` 会保留已有说明。**说明和输入/输出提示是给使用者看的文档，不会自动注入模型提示词，也不是结构化输入输出校验规则。** 运行要求仍应写在实际任务或节点提示词中。

样例对应的 `details` 数据例如：

```json
{
  "description": "根据给定材料生成带证据的中文简报",
  "instructions": "输入应包含材料正文和来源；先人工检查材料是否完整。",
  "input_hint": "材料正文、来源和本次关注点",
  "output_hint": "结论、证据、待核实项",
  "test_cases": [
    {
      "name": "材料不足时保留不确定性",
      "input": "只知道项目名称，没有源码和运行日志。请给出审查结论。",
      "must_contain": ["待核实"],
      "must_not_contain": ["已验证全部通过"]
    }
  ]
}
```

最多保存 5 个样例，每个输入最多 8 KiB；每个样例必须有 1–8 条非空文本断言，单条最多 1 KiB。必含和禁含项不能相互矛盾。断言只做区分大小写的字面子串匹配，不运行正则、表达式或脚本，也不会让另一个模型打分。

文本通过只能证明输出满足这些明确的文本条件，不能证明内容正确、事实充分，或技能包在所有任务上优于单技能。

## 免费本地预检与 AI 分析的区别

| 操作 | 做什么 | 模型调用与费用 |
| --- | --- | --- |
| 本地预检 | 核对技能引用、依赖清单、图结构、目标执行模式、部分环境元数据及正文大小 | 不调用模型，不产生模型费用 |
| AI 依赖分析 | 在预检结果与受限静态材料上，推断可能还缺少什么，给出处理建议 | 调用所选服务商，计入辅助分析费用 |
| 对照评测 | 对同一输入分别运行主技能和完整技能包，再检查文本断言 | 实际模型运行，计入辅助分析费用 |

预检报告区分以下状态：

| 状态 | 证据范围 |
| --- | --- |
| `present`：找到证据 | 找到命令、配置声明、技能文件索引或包元数据；不等于已经执行成功 |
| `missing`：未找到 | 在明确的检查范围内未找到必需项，或指定精确版本不匹配 |
| `blocked`：目标环境禁用 | 当前执行方式不允许使用该工具或能力 |
| `unchecked`：未核实 | 未选目标环境、无法完整读取、无法判断权限或尚不能验证版本要求 |

预检按照实际运行路径解释权限：任务使用任务策略，工作流使用本地只读模式，快捷运行和按钮按各自的执行方式判断。预授权列表中没有某个工具，不等于该工具被禁用。找到 Python 命令也不等于工作流可以执行它：工作流的 Shell 禁用项仍会单独报告。

环境检查只读取必要的元数据：

- 命令只通过应用进程的 `PATH` 查找，不执行 `--version`。
- Python 包只读取明确选定虚拟环境的 `dist-info/METADATA`，不运行解释器或导入包。未指定环境、版本范围尚不支持或元数据不完整时保留“未核实”。选环境只影响检测，不会自动激活任务环境。
- 环境变量只判断是否声明，不保存或返回值，不读取 `.env` 或密钥库。
- `file` 核对技能版本内的文件索引，不扫描用户工作目录。
- MCP 核对已安装插件的启用和授权元数据，不连接服务，不验证凭据有效性。

预检不会安装依赖、执行技能脚本或扩大权限。AI 分析也不会执行目标任务；它在独立空目录中禁用所有模型工具与 MCP。AI 对“已安装”或“缺失”的自述仍按未核实的推断展示，不能覆盖程序已有的确定性结论。AI 分析单次最多 3 分钟、预算上限 1 美元；已有更严格的全局限制继续生效。

## 查看上下文大小

预检按每次运行分别统计技能 `SKILL.md` 的正文大小，工作流按每个节点分别统计。同一个技能被两个独立步骤使用，不会把两步误算成同一次上下文。

- 单次技能正文累计上限为 **256 KiB**；运行前超过上限会拒绝，不会悄悄截断辅助技能。
- 接近上限时会提示精简正文、把详情放入按需读取的资源，或拆分独立步骤。
- Token 数只按 ASCII 约 4 字符/token、非 ASCII 约 1 字符/token 粗估，不是服务商实际用量，也不是模型上下文窗口大小。
- 这个统计不包含任务提示词、包装指令、工具结果等额外内容。旧 Claude 兼容路径仍可能受到较小的 16 KiB 指令参数限制。

## 明确采用升级或回退

从技能包套用到任务、快捷运行或工作流节点时，会同时记录来源包 ID 与来源版本。之后发布新包版本，不会自动修改已有任务或节点。

在包的使用与升级预览中，可以查看引用它的任务和节点、当前来源版本、目标版本的成员与主辅角色变化。选择历史版本也可以作为回退目标。

| 来源状态 | 含义与操作 |
| --- | --- |
| `linked` | 当前声明的成员和来源版本一致，可以明确采用目标版本 |
| `modified` | 本地改过成员、主辅角色、顺序或版本模式；先在编辑器中审阅并重新套用，不能被升级操作覆盖 |
| `detached` | 没有包来源，或用户主动脱离组合；只按当前成员绑定使用 |
| `missing` | 来源版本无法读取，不能假定仍与该版本一致 |

把固定成员改成“跟随当前”会标记为本地修改，即使当前碰巧仍解析到相同版本。旧任务没有来源信息时保持独立绑定，不根据成员相似度反推它属于哪个包。

采用以用户选定的单个任务或节点为单位，提交时还会检查对象版本。其他页面已经保存了修改时，旧预览会被拒绝，需要刷新后重新审阅；没有“强制覆盖本地修改”的升级入口。明确脱离组合会保留成员，仅去掉来源。

运行记录固定实际成员版本和来源信息。工作流在冻结 `follow` 绑定前记录声明状态，因此“本地改为跟随当前”不会因本次刚好解析到旧版而丢失修改标记。删除包列表条目不会改写已有任务成员或历史运行；历史来源也不会因此自动变成新的包。

## 如何理解“已加载”证据

运行页的 `loaded` 表示 Tidebot 已准备并记录该技能版本的运行材料，以及主技能或辅助技能角色。它证明材料被提供给运行环境，**不证明模型实际阅读、调用或依赖了该技能**。

当前没有可靠的逐技能实际执行归因，不会把最终回答中的“我使用了某技能”当证据。旧记录只有一个技能名称或主技能字段、缺少完整运行快照时，也不会补造 `loaded` 事件。需要核对具体行为时，仍应结合实际工具调用日志、输入输出与人工检查。

## 主技能与完整技能包的对照评测

在已保存的技能包版本上添加非空断言样例后，可以明确发起对照评测。每个样例使用相同输入、固定的包成员版本、服务商与模型，顺序运行两次：一次只提供主技能，一次提供完整组合。主技能基线特意省去辅助技能，仅用于对照；这不放宽普通任务运行对必需依赖的要求。

结果保留每组输出、断言通过情况、耗时、Token、费用和子运行链接。`completed` 表示评测流程完成，样例是否通过要看各自断言；两组都通过也不代表辅助技能带来了质量提升。断言不通过会保留结果并继续比较，模型调用失败才会停止后续运行。输出只保留前 64 KiB 供评测页展示并标记截断，文本断言检查使用评测页截断前的运行结果文本。

评测有明确的执行边界：

- 每次使用独立临时目录，仅允许 `Read`、`Glob`、`Grep`，禁用编辑、写文件和 Shell；**所有 MCP 均关闭**。
- 预检确认必需的命令、Python 包执行、MCP 或其他工具被禁用时，不启动评测。它适合核对该受限环境中的文本输出，不能验收需要外部系统或脚本执行的完整业务任务。
- 每批预算为 0.02–5 美元，顺序分配到样例的两组调用；每个子运行最多 3 分钟，仍受全局预算与并发队列限制。
- 同时只运行一批对照评测；可主动取消。某次运行失败、预算不足或服务商配置改变时停止后续调用，不自动扩大预算或换模型。
- 退出或崩溃后的未完成评测标记为中断，不自动重放。对照结果不会自动升级技能包、改写任务绑定或替用户选择获胜版本。

这些边界不同于普通工作流：普通工作流虽然本地文件工具只读，但仍沿用已批准的 MCP。不能用评测通过来推断这些外部连接器也已验证。

## 数据与接口兼容

来源记录使用新增迁移 `030_run_skill_set_sources.sql`，对照评测使用 `031_skill_set_evaluations.sql`。它们不批量改写原始技能正文或旧任务。旧版技能包 ZIP 缺少说明和样例时按空说明处理；本轮仍使用原有 `tidebot-skill-set/1` 包格式。

开发或集成可使用以下入口，全部沿用本地 WebUI 的认证与写操作保护：

| 入口 | 用途 |
| --- | --- |
| `GET/PUT /api/skill-manifests/{skill_id}` | 读取或版本化编辑 `tidebot.json`；写入带 `expected_version_id` |
| `POST /api/skill-sets/preview` | 预览依赖补全；不写入、不自动采用 |
| `GET/POST /api/dependencies/preflight` | 不调用模型的本地预检 |
| `GET /api/skill-set-usage?set_id=...&target_version_id=...` | 来源、历史版本和采用影响预览 |
| `POST /api/skill-set-usage/apply` | 对一个已关联且未本地修改的任务/节点采用目标版本；校验对象版本 |
| `POST /api/skill-set-evals` | 明确发起一批固定版本的付费对照评测 |
| `GET /api/skill-set-evals/{id}` / `POST /api/skill-set-evals/{id}/cancel` | 查看或取消评测 |

本地单元测试和模拟执行可以验证依赖展开、并发冲突、权限参数、快照及断言逻辑。它们不能替代真实模型、真实 MCP、外部服务或第三方脚本的端到端验收；本文也不表示已经将完整浏览器回归接入 CI。
