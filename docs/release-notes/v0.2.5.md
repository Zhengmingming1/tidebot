# v0.2.5

## 中文

本次补丁改善更新恢复、凭据与文件访问安全、技能版本一致性及桌面布局。

- 更新回滚失败时保留可执行文件和恢复副本；Windows 恢复成功后，清理被锁定的旧文件失败不再阻止重新启动。
- 两步验证恢复码改为原子消费。已有凭据存储的密钥缺失、损坏或不可读时明确报错，不再静默替换密钥。
- 会话文件查找和搜索通过同一已打开的根目录执行，收紧符号链接及目录替换风险，并在读取时限制大小。技能仓库逐级检测大小写折叠及文件/目录路径冲突。
- 版本指针与操作日志在同一事务中提交；技能回退拒绝不属于该技能的版本。
- 代理地址省略协议或格式异常时也会隐藏凭据。邮件地址列表正确处理带引号的显示名和分号分隔，拒绝无效地址及换行注入。
- 通知摘要正确限制为 8 个非空行，保留字符上限；订阅发现补齐 `/rss` 路径。静默时段遇到夏令时跳过的边界时移至首个有效时刻。
- 技能元信息结束分隔符须独占一行；插件枚举校验区分 JSON 类型，数组配置保留原始选项值。
- 初始窗口适配所在显示器可用区域；修复扩展页面加载冲突，改善会话历史滚动、长选项及窄窗口布局，折叠工作流高级设置以腾出画布空间。
- 更新固定提交版本的 Docker 登录 Action，并补充回归测试。

### 升级与验证边界

相对 v0.2.4 没有新增数据库迁移或 Go 模块依赖变更。升级前建议备份数据库和凭据恢复材料；从更早版本升级仍会执行既有迁移。密钥丢失需恢复原密钥，新密钥无法解密旧数据。

发布工作流在跨平台完整矩阵通过后才打包。响应式浏览器几何与截图验收因环境限制未执行，自动化测试不替代真实桌面显示或第三方服务验收。

平台代码签名与更新清单签名不同：未配置平台证书时，macOS 使用 ad-hoc 签名，Windows 未签名，系统仍可能提示来源风险。公开更新渠道另用 ed25519 清单签名和 SHA-256 校验。

## English

This patch improves update recovery, credential and file-access safety, version consistency, and desktop layouts.

- Preserve recovery files on rollback failure; locked-file cleanup no longer prevents Windows relaunch after a successful restore.
- Consume recovery codes atomically and reject missing or invalid keys for existing credential stores.
- Confine session file search to an opened root, bound reads, and reject colliding skill-repository paths.
- Commit version pointers and audit records together; reject unrelated skill rollback targets.
- Redact malformed proxy credentials and fix email lists, excerpt limits, RSS discovery, daylight-saving boundaries, frontmatter delimiters, and typed plugin enums.
- Fit initial windows to usable display space and improve extension loading, chat scrolling, dropdowns, and workflow layouts. Update the pinned Docker login Action and add regressions.

No new migrations or Go module changes relative to v0.2.4. Back up data and recovery material; a replacement key cannot decrypt an existing store. Earlier migrations still apply to older installations.

Packaging follows the full cross-platform matrix. Browser geometry and screenshot checks remain unexecuted due to environment restrictions. Without platform certificates, macOS uses ad-hoc signing and Windows remains unsigned. Signed update manifests and checksums are separate from platform code signing.
