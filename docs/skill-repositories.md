# Skill 仓库使用指南

Tidebot 的「Skill 仓库」可以登记远端 Git 仓库，浏览其中的技能，再把选中的完整目录安装到技能库。安装后的技能沿用现有任务、技能组合、工作流和版本回退能力。

仓库功能从 v0.2.1 开始提供，v0.2.2 增加内置公开来源和常显字段帮助。安装包见 [v0.2.2 发布页](https://github.com/Zhengmingming1/tidebot-releases/releases/tag/v0.2.2)。

## 1. 支持的来源与连接条件

统一通过 Git 接入 GitHub、GitLab、Gitee 和公司自建 Git，接受 HTTPS、SSH 以及 `git@host:group/repo.git` 形式的克隆地址。公司仓库可以使用自定义域名、端口和多层子组路径。

分支或标签、扫描目录分别填写；不需要把目录或分支拼进仓库地址。分支留空时读取远端默认分支。首版要求使用 Git 克隆地址，不把平台网页的 `tree`、`blob` 链接自动转换为克隆地址。

运行 **Tidebot 服务进程的机器和账号** 必须具备以下条件：

- 已安装 Git，且 Tidebot 进程可以找到它；程序不会自动安装 Git。
- 私有 HTTPS 仓库已配置可用的 Git 凭据管理器。
- SSH 仓库已配置 SSH 密钥或 agent，并已信任服务器的主机身份。
- 公司网络、代理和 HTTPS 证书信任配置可用。

桌面登录账号和远端部署账号不一定相同。浏览器能打开仓库页面，也不代表 Tidebot 服务账号能通过 Git 访问它。

连接使用非交互方式。缺少凭据、Git、证书信任或 SSH 主机信任时，页面报告失败原因；后台不会停留在密码输入提示。Tidebot 不收集仓库密码，也不把带密码或 Token 的 URL 保存进仓库记录。首版不提供平台 OAuth 登录流程，不接受 HTTP 明文仓库、本地路径、`file://` 或 `ext::` 来源。

## 2. 添加、扫描和选择技能

### 使用内置公开仓库

「Skill 仓库」列表中的「内置公开仓库」提供以下来源。即使已经添加其他仓库，这个入口仍会显示。

| 来源 | 仓库 | 预置扫描目录 |
|---|---|---|
| Anthropic Skills | [anthropics/skills](https://github.com/anthropics/skills) | `skills` |
| OpenAI Plugin Skills | [openai/plugins](https://github.com/openai/plugins) | `plugins` |
| Vercel Agent Skills | [vercel-labs/agent-skills](https://github.com/vercel-labs/agent-skills) | `skills` |

点击「查看原仓库」可查看来源内容。点击「一键添加并扫描」会保存仓库地址与扫描目录，并读取远端默认分支；扫描成功后进入仓库技能列表。这个操作不会安装任何 Skill，也不会启用插件或 MCP。

已有匹配来源时，卡片提供浏览入口，不重复创建同一预设。扫描失败后，已保存的仓库记录保留，可以进入该仓库点击「扫描 / 检查更新」重试。打开页面本身不会触发预设仓库的网络下载。

OpenAI 入口采用当前 `openai/plugins`。旧 `openai/skills` 已在其 README 标记弃用，不再作为内置来源。预设只代表来源入口；各技能的许可、第三方工具、插件级 MCP、目录外资源与运行环境仍需分别检查，不代表已经兼容或验收。

### 手动添加其他仓库

1. 打开「技能」区域的「Skill 仓库」页签。
2. 点击「添加仓库」，填写克隆地址。可选填名称、分支或标签、扫描目录。
3. 保存后进入仓库页面，点击「扫描 / 检查更新」执行首次扫描。
4. 按名称、说明或路径搜索，也可以按安装状态筛选。
5. 打开单个技能预览，或勾选多个技能批量预览。
6. 查看 `SKILL.md`、文件树与兼容提示，再点击安装。

添加与编辑表单把 Git 地址、分支和扫描目录说明直接放在字段下方，无需悬停提示图标。

扫描会递归寻找 `SKILL.md`。根目录单技能、`skills/<name>/`、`.agents/skills/<name>/` 和插件目录内的技能都可被发现。名称与说明来自技能正文的 frontmatter；目录路径用于区分同名候选。

扫描中可以取消。失败时保留上次成功的目录及扫描时间，不把超时、无权限或扫描失败显示为「没有技能」。

## 3. 安装范围与兼容限制

安装包含所选技能目录内的全部普通文件，包括脚本、参考资料、资源和 `tidebot.json`。不会只下载 `SKILL.md`，也不会把整仓库注册为一个 Skill。

父、子目录同时包含 `SKILL.md` 时，列表提示嵌套关系。选择父技能会携带其子目录文件，但不会自动把子技能注册成另一个本地技能。

以下边界适用于首版：

| 内容 | 处理方式 |
|---|---|
| 符号链接、Git 子模块 | 所选技能目录中出现时拒绝安装，避免静默丢文件 |
| Git LFS 指针 | 读取文件时拒绝作为实际资源导入；扫描列表不保证提前识别所有资源中的 LFS 指针 |
| 目录外共享脚本、跨目录引用 | 不自动扩大安装范围；可识别的引用给出提示，复杂引用仍需人工检查 |
| 插件 hooks、插件 MCP 配置 | 不随 Skill 启用 |
| 脚本依赖、外部服务凭据 | 不自动安装或配置 |
| 脚本执行权限位 | 沿用现有技能链路，不保留 Git 的可执行位；依赖直接执行 `./script` 的技能需调整调用方式或运行环境 |

每个技能最多 2000 个文件，单文件不超过 10 MiB，总文件内容不超过 50 MiB。路径和文件类型会校验；不兼容的候选不会静默截断后安装。

安装完成后可查看技能、检查依赖或运行。依赖检查与运行的具体边界见[技能包的依赖、预检、升级与对照评测](skill-manifests.md)。安装成功不等于第三方脚本、模型或外部服务已经通过运行验收。

## 4. 同名技能与批量安装

技能来源按仓库地址、跟踪分支或标签、技能目录识别，不按显示名称猜测。

- 同来源重复安装会识别已有技能；相同内容复用现有版本。
- 不同来源同名时返回名称冲突，并建议一个可用的本地名称。修改名称后重试，不覆盖原技能。
- 已安装来源可选择「另存为独立副本」。副本保留该版本的来源信息，但不接入原技能的更新订阅。
- 批量安装逐项提交。成功项保留，失败项显示原因；修正后可重试未成功的条目。

本地显示名与技能内部调用名是两件事。两个同名技能可以分别安装和运行；放入同一组合时，如果内部调用名冲突，仍沿用现有规则明确拒绝。本功能不会自动改写上游 `SKILL.md` 来解决冲突。

## 5. 检查更新、下载与采用

仓库页面的刷新由用户发起，没有后台自动升级。只有技能目录内容变化才提示更新；仓库中无关文件的提交不会使所有技能都显示新版本。

更新分成两个动作：

1. **下载新版**：预览文件差异与引用情况，将上游内容保存为技能历史版本，保留当前版本。
2. **采用新版本**：用户明确采用，移动技能的当前版本指针，并更新该来源的已采用基线。

采用前会比较当前版本与预览时的版本。另一个页面或进程已修改当前版本时，过期请求被拒绝，需要重新预览。这是并发版本校验，不会自动合并变更。

本地内容相对上次采用的上游版本发生变化时，会显示「本地已修改」。可以保留本地、把上游另存为副本，或在查看差异后明确采用上游内容。远端内容恰好等于一个已有本地版本时会复用该版本；仍可明确采用以更新来源基线。

已下载但未采用的版本可从技能详情的来源区域继续比较和采用。回退使用技能详情原有的历史版本入口。

采用新版的影响如下：

| 使用方式 | 采用后的行为 |
|---|---|
| 跟随当前版本的任务或工作流节点 | 下一次运行解析为新版 |
| 固定到具体版本的绑定 | 保持原版本 |
| 已保存并冻结成员版本的技能组合 | 保持组合中的原绑定，需要明确更新组合 |
| 已启动的运行 | 保持该次运行的技能快照 |

任务、组合与工作流的绑定规则见[技能组合与工作流说明](skills-workflows.md)。

## 6. 缓存、清理与移除来源

Tidebot 使用不检出工作区的浅层 Git 缓存，读取固定提交中的文件。预览与安装锁定同一提交，后续刷新分支不会把已预览的内容悄悄替换为新版。

v0.2.2 起，扫描与安装通过有大小上限的 Git 批量对象读取完成，减少逐文件启动进程和只读缓存遍历。对象身份、类型、大小与输出完整性仍会校验；会写入缓存的操作继续检查缓存上限。

浅克隆仍可能获取仓库当前快照中的未选文件对象。**按需安装不等于网络只下载所选目录。** 扫描目录限制的是候选范围，不保证减少首次传输量。

每个仓库缓存上限为 256 MiB，Git 操作有超时和取消控制。大仓库或频繁刷新后超过缓存限制时，需要清理缓存或换用更小的技能仓库。此限制不是整个 Tidebot 数据目录的总配额。

「清理缓存」保留仓库配置和已安装技能，但会使现有安装预览失效；之后需重新刷新仓库。

「移除仓库」移除登记和缓存，保留已安装技能、历史版本和来源快照。远端目录删除或改名也不会卸载本地技能；界面显示来源失效，不自动按相似名称绑定到其他目录。

## 7. 验证范围

自动化测试覆盖本地 Git 仓库对象读取、多个技能目录、固定提交快照、资源完整性、不支持的文件类型和大小限制；服务层测试覆盖同名隔离、重复安装、更新与采用分离、过期版本拒绝、事务失败回滚，以及移除来源后保留技能。

本地 Git fixture、HTTP 测试或模拟浏览器测试，不等于已验证每种托管平台和每家公司的实际环境。GitLab、Gitee、公司 Git 的认证、代理、证书、SSH 配置和大仓库性能，需要在获授权的真实环境中验证。通过某个公共仓库连接，也不能据此断言私有仓库可访问。
